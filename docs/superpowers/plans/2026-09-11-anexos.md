# Anexos nas mensagens — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Uma mensagem pode ter um anexo (imagem, vídeo, documento ou áudio) que sai junto com o texto em cada grupo, no agendamento e no "Enviar agora".

**Architecture:** O arquivo fica em `data/media/<id>.<ext>` e os metadados dentro da mensagem (`media`). O upload vai em base64 no próprio `POST`/`PUT` da mensagem. O `broadcast` lê o arquivo uma vez e, por grupo, manda o anexo com o texto como legenda (ou anexo e texto separados quando a legenda não cabe ou é áudio) por `sendMedia`, que escolhe o endpoint do WAHA pelo tipo. A tela ganha "Anexar" no editor, prévias por tipo e o anexo nas listas e no modal.

**Tech Stack:** Node 18+, ES Modules, `node:http`, `node:fs`, `node:test`, HTML/CSS/JS vanilla. Nenhuma dependência nova.

**Spec:** `docs/superpowers/specs/2026-09-11-anexos-design.md`

## Global Constraints

- Dependências: só `node-cron` e `dotenv`. Sem multipart, sem biblioteca de imagem.
- Nomes em inglês; mensagens ao usuário em português. Erros sempre `Error` com contexto.
- Sem `console.log`; logger.js. JSDoc só em exportadas. Sem classes.
- **Nunca enviar mensagem real.** Testes com client injetável ou `fetch` falso; navegador contra o mock.
- **Não alterar `harness/`.** O mock só conhece `sendText`; o log de envios só ganha campo aditivo.
- Todo HTML interpolado passa por `escape()`.
- Regressão ao fim de cada task: `npm test && node harness/run.js all`.

### Task 1: `src/media.js`

**Interfaces (Produces):**
- `MAX_MEDIA_BYTES = 16 * 1024 * 1024`
- `classifyMedia(mimetype): 'image'|'video'|'audio'|'document'` (qualquer mimetype válido é aceito; imagem só jpeg/png/webp; gif vira `document`)
- `safeExtension(filename): string` (só `[a-z0-9]{1,8}`, minúsculas; senão `bin`)
- `mediaDirFor(schedulesPath): string` → `<dir>/media`
- `saveMedia(dir, { filename, mimetype, data }, { maxBytes? }): { id, filename, mimetype, size, kind }` — valida, decodifica base64, grava `<id>.<ext>`
- `mediaPath(dir, media): string`
- `removeMedia(dir, media): void` (ausente não é erro)
- `readMediaBase64(dir, media): string` (lança "Anexo não encontrado: <filename>")

- [ ] Testes em `test/media.test.js`: classificação (jpeg→image, gif→document, mp4→video, mpeg→audio, pdf→document), `safeExtension('Foto.JPG')==='jpg'`, `safeExtension('a.b/../c')==='c'`, `safeExtension('semext')==='bin'`; `saveMedia` grava e devolve metadados com `size` real; `saveMedia` recusa base64 inválido, mimetype fora do formato `tipo/sub`, filename vazio e tamanho acima de `maxBytes` (com `maxBytes: 10` no teste), sem deixar arquivo; `removeMedia` apaga e não reclama de ausente; `readMediaBase64` devolve o conteúdo e lança com o nome quando falta.
- [ ] Implementar. Commit: "Módulo de mídia: tipos, gravação e leitura dos anexos".

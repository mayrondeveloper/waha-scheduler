# Cliques por disparo — plano

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada disparo com link mostra quantos cliques teve, no total e por grupo, com o link enviado com prévia do destino (título, descrição e imagem).

**Architecture:** Um redirecionador (`src/redirect/`, processo separado, Node 24 com `node:sqlite`) cria links rastreáveis por (disparo, grupo, URL), redireciona com 302 e conta os cliques. O agendador e a tela viram clientes dele: antes de enviar, o agendador gera um `dispatchId`, pede os links, busca o Open Graph do destino e manda por `link-custom-preview`; se algo falhar, o texto sai como hoje. O histórico agrupa por `dispatchId` e consulta os cliques pelo servidor local.

**Tech Stack:** Node 24 (`node:sqlite`, `node:crypto`, `node:http`), `node:test`, tela em módulos ES.

**Spec:** `docs/superpowers/specs/2026-09-11-cliques-por-disparo-spec.md` e `docs/superpowers/specs/2026-09-12-cliques-implementacao-design.md`

## Global Constraints

- Sem dependência nova. O redirecionador exige Node 24 (`node:sqlite`); o resto do projeto segue em Node 18+. Os testes do redirecionador pulam quando `node:sqlite` não existe.
- O envio nunca depende do rastreador nem da prévia: qualquer falha degrada para `sendText` com os links originais, uma tentativa só por endpoint.
- Mensagens reais: nenhuma. A verificação usa o mock (sem `link-custom-preview`: prova a degradação) e o redirecionador local.
- Harness intocado e verde.

### Task 3: Agendador e tela como clientes: links, prévia e envio

**Files:**
- Create: `src/links.js`, `src/preview.js`
- Modify: `src/config.js` (`clicksUrl`, `clicksApiKey`), `src/waha/client.js` (`sendTextWithPreview`), `src/broadcast.js`, `src/index.js`, `src/ui/routes/actions.js`, `src/schedules.js` (`utm` no agendamento, default true), `src/ui/routes/schedules.js` (`utm` no corpo)
- Test: `test/links.test.js`, `test/preview.test.js`, `test/broadcast-links.test.js`, `test/waha-client.test.js` (preview), `test/schedules-lists.test.js` (utm)

**Interfaces:**
- `findUrls(text)` → URLs http(s) únicas na ordem, sem pontuação final (`.`, `,`, `)`, `!`, `?`); `rewriteLinks(text, map)` → texto com cada URL trocada; `requestLinks({ dispatchId, schedule, groups, urls, utm }, cfg, { fetchImpl, timeoutMs = 2000 })` → `{ links }` ou lança com contexto.
- `fetchOpenGraph(url, { fetchImpl, timeoutMs = 5000, maxBytes = 1_000_000, now })` → `{ url, title, description, image } | null`; cache em memória por URL por 1 h (`clearPreviewCache()` para os testes).
- `sendTextWithPreview(chatId, text, preview, cfg)` → `POST /api/send/link-custom-preview` com `{ session, chatId, text, preview: { url, title, description, image: { url } } }`.
- `broadcast(message, groups, { ..., links = null, preview = null })`: por grupo, `text = rewriteLinks(spin(message), links?.[chatId] ?? {})`; sem anexo e com `preview`, tenta `sendTextWithPreview` com `preview.url = links?.[chatId]?.[preview.url] ?? preview.url`; falhando, `sendText` e linha com `preview: 'failed'`. Linhas do log ganham `dispatchId`, `tracking` e `links` (quantidade) via `extra`.
- Preparação do disparo em `src/dispatch.js`: `prepareDispatch({ schedule, message, targets, cfg, groupNames })` → `{ dispatchId, links, preview, tracking, extra }`: gera `dispatchId`, acha URLs; sem URLs → `tracking: 'off'`... não: `'none'` (sem link); cliques desligados na config → `'off'`; pede links (falha → `'unavailable'`); busca a prévia do primeiro link (falha → nulo). Usado por `index.js` (cron, tique) e por `actions.js` (run).

- [ ] Testes: URLs com pontuação em volta; troca preserva formatação; timeout devolve indisponível; OG extraído, sem `og:title` nulo, HTML cortado no limite, cache; broadcast com prévia, degradação, `dispatchId` em toda linha; `utm` no agendamento.
- [ ] Implementar; commit `Disparo com identidade, links rastreáveis e prévia do destino`.
